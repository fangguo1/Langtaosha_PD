# GOAL_20260629

## Goal

为 `smart_search` 增加 query correction 确认流程：当 Query Understanding 给出 `corrected_query` 且与原 query 不一致时，第一次请求不直接执行检索，而是返回确认提示；用户确认后，再按纠错词或原 query 执行 `hybrid_retrieval`。

## Affected Modules

- `src/docset_hub/indexing/paper_indexer.py`
- `app/routes/scholar.py`
- `templates/langtaosha_smart_search.html`
- `tests/indexing/test_paper_indexer.py`
- `tests/app/test_scholar_routes.py`

## Main Risks

- 现有 `smart_search()` 已被路由和测试假设为“单次请求直接返回结果”，新增确认态后可能影响 API 消费方。
- `query_correction` notice 目前只是一条展示文案，需要和新的确认参数协议保持一致。
- 前端 `search-use` 页面当前点击 notice action 会直接把 `mode/query` 改写后重查，需要改成携带确认决策参数，避免破坏作者建议和 vector fallback 现有行为。

## Intended Implementation Steps

1. 在 `paper_indexer.smart_search()` 中增加 correction decision 入口，并在未确认时返回 `needs_confirmation` 状态与空结果。
2. 在 `app/routes/scholar.py` 中解析新的确认参数，并把未确认状态映射为 `notice + 空结果` 的 API 响应。
3. 调整 `query_correction` notice 结构，提供 accept/reject 两个动作所需参数。
4. 更新 `search-use` 前端页面逻辑：收到 correction notice 时触发二次请求，而不是默认直接展示本次结果。
5. 更新 indexing 与 route 测试，覆盖未确认、accept、reject 三种路径。
6. 先做本地静态/语法验证，再在最终说明中区分可由 Codex 验证的部分与需用户在真实环境验证的部分。
